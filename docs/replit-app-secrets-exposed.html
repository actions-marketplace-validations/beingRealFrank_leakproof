Are the API keys in my Replit, Lovable or Bolt app exposed?

When an AI tool hits "API key not found" in the browser, the quickest fix it knows is to rename the variable with a public prefix. The error goes away, and the key is now in the JavaScript every visitor downloads.

1. Which prefixes are public

Anything starting with NEXT_PUBLIC_ (Next.js), VITE_ (Vite, which Lovable and Bolt projects use), EXPO_PUBLIC_ (Expo) or REACT_APP_ (Create React App) is copied into the browser bundle at build time. Never public: OpenAI, Anthropic or other AI keys, Stripe secret or restricted keys, the Supabase service_role key, database URLs, webhook signing secrets.

2. Find them in your code

grep -rnE "(NEXT_PUBLIC|VITE|EXPO_PUBLIC|REACT_APP)_[A-Z0-9_]*(SECRET|SERVICE_ROLE|PRIVATE|OPENAI|ANTHROPIC|DATABASE_URL|WEBHOOK)" \
  --exclude-dir=node_modules --exclude-dir=.git .

3. Check what actually shipped

npm run build
grep -rnoE "sk_live_[A-Za-z0-9]{10,}|sk-(proj-)?[A-Za-z0-9_-]{20,}|sk-ant-[A-Za-z0-9_-]{20,}|sb_secret_[A-Za-z0-9_-]{10,}" .next/static dist build 2>/dev/null | head

4. Move the call to a server and rotate

Vite apps have no server of their own: put the call in a Supabase Edge Function, read the key there with Deno.env.get('OPENAI_API_KEY'), and set it with supabase secrets set OPENAI_API_KEY=…. Removing a key from the code doesn't un-leak it: create a new key in the provider's dashboard, deploy with it, then delete the old one. Also set a monthly spend limit in the OpenAI or Anthropic console, so a leaked key costs a known amount.

Firebase rules leak check

Your Firebase web config is public by design, so your security rules are the only thing between it and your users' data. AI tools often leave them in test mode or set them to if true until the app "works". This check finds those rules in your repo.

Run the free scanner

One command, runs locally, nothing is uploaded except an optional dependency lookup:

npx github:beingRealFrank/leakproof

Add --offline to skip that lookup. It is also a GitHub Action that runs on every pull request.

What it reports

Output on a small sample project with an open firestore.rules:

CRITICAL LP006 Firebase security rules open to everyone
         firestore.rules:2  allow read, write: if true;
         Anyone on the internet can read, write this data with your public Firebase config.
         Fix: Require auth and ownership, e.g. allow read, write: if request.auth != null && request.auth.uid == resource.data.uid;

Check it from the outside

Signed out, a private collection must refuse to list:

curl "https://firestore.googleapis.com/v1/projects/<project-id>/databases/(default)/documents/<collection>?pageSize=5"

You want 403 PERMISSION_DENIED. If you get documents back, anyone on the internet can too.
